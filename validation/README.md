# Level 0 Validation Protocol

更新日: 2026-08-16

## 1. 現在のマイルストーン

次の開発ゲートは `Level 0 v1.0 pilot-validated` です。Level 1の量産、用語数の拡大、新機能の追加は、このゲートを通過するまで行いません。

Level 0の18章が存在し、構造検査とブラウザ検査を通ったことは確認済みです。しかし、それだけでは学習効果を確認したことにはなりません。この検証では次を分けて扱います。

| 段階 | 確認すること | 状態 |
|---|---|---|
| Structural complete | 18章、予想、証拠、演習、4軸診断、出典が存在する | 完了 |
| Creator walkthrough | 全章を実際に履修し、長さ・重複・読み飛ばし・操作上の摩擦を記録する | 未実施 |
| Novice pilot | 天文学初学者3〜5人が説明なしで使い、Pre/Postと行動観察を行う | 未実施 |
| Pilot-validated v1.0 | 事前に決めたゲートを満たし、重大問題を修正後に再確認する | 未達 |
| Educational effectiveness | より大きく多様な標本で、保持と転移を含む効果を評価する | 将来 |

3〜5人のテストは、頻出する混乱や操作上の問題を発見する形成的評価として有効です。一般の学習者に対する教育効果を証明したとは表現しません。

## 2. 検証で答える問い

1. 初学者は説明なしでL0-01を開始し、次の章へ進めるか。
2. 18章を通して、どこで止まり、読み飛ばし、二度読むか。
3. 用語、概念、推論、証拠・データ、科学的判断は受講前後でどう変わるか。
4. 学んだ説明を、本文と異なる事例へ移して使えるか。
5. 7〜14日後にも中心概念と考え方が残るか。

## 3. 参加者とプライバシー

- Creator walkthroughは作者自身が行います。教材を知っているため、学習効果ではなくUXと編集上の問題だけを評価します。
- Novice pilotは、大学天文学を履修しておらず、天文学を専門的に学んだ経験がほぼない3〜5人を対象にします。
- 可能ならスマートフォンとデスクトップ、理系・非理系を混ぜます。
- 氏名、メールアドレス、自由記述中の個人情報はリポジトリへ保存しません。参加者IDは`P01`のような番号だけを使います。
- 画面や音声を記録する場合は、開始前に目的、保存期間、削除方法を説明し、明示的な同意を得ます。
- 生ログは`validation/results/`またはリポジトリ外へ保存します。このディレクトリはGit管理対象外です。

## 4. 実施順序

### A. バージョンを固定する

開始前に本番URL、コミットSHA、実施日を記録します。同じpilotの途中では教材を変更しません。重大な科学誤りや進行不能を見つけた場合は中断し、修正版を別の検証ラウンドとして扱います。

### B. Creator walkthrough

L0-01からL0-18まで通常の学習者と同じ操作で進み、`level-0-lesson-log.csv`を1章ごとに記入します。

- 開始・終了時刻
- 面白さ、分かりやすさ、難易度、長さ
- 分からなかった用語
- 前章へ戻った箇所
- 重複した説明
- 「なるほど」と思った箇所
- 読み飛ばした箇所
- 迷った操作

作者は内容を知っているため、Pre/Postの改善量には含めません。

4つの評定は次の向きへ固定します。

| 項目 | 1 | 3 | 5 |
|---|---|---|---|
| 面白さ | 続けたいと思わない | どちらでもない | さらに知りたい |
| 分かりやすさ | 説明を追えない | 一部は説明できる | 自分の言葉で説明できる |
| 難易度 | 簡単すぎる | ちょうどよい | 難しすぎる |
| 長さ | 短すぎる | ちょうどよい | 長すぎる |

自由記述にカンマを含める場合は、CSVセル全体をダブルクォートで囲みます。空欄と「問題なし」を区別し、観察したが問題がなかった場合は`none`と記録します。

### C. Novice pilot

1. コースを見せる前に`level-0-assessment.md`のForm Aを20分以内で受けてもらいます。
2. URLだけを渡し、「Level 0を順番に進めてください」と伝えます。操作説明や内容の補足はしません。
3. 参加者は各章の直後に学習者欄を記録します。観察者は、停止、読み飛ばし、再読、誤答、迷ったクリックを事実として記録します。
4. 全18章の終了後24時間以内にForm Bを25分以内で実施します。
5. 7〜14日後に、Form Bのうち記憶ではなく説明と転移を問う設問3〜10を再実施します。
6. 最後に「分かりやすかったですか」ではなく、行動を具体化する質問をします。

採点時は答案から参加者ID以外を外し、Pre/Post/Delayedの別が採点者に見えない順序へ並べます。3〜5人のpilotでは全答案を二人が独立採点し、不一致をルーブリックへ戻って合意します。二人目を確保できない場合は、その制約と再採点の有無をレポートへ明記します。

聞き取りでは次を使います。

- 最初に何をすればよいと判断しましたか。
- やめようと思った箇所はどこですか。その直前に何がありましたか。
- 読み飛ばした見出しはどれですか。なぜ飛ばしましたか。
- 二度読んだ説明を、自分の言葉で説明できますか。
- もっとも記憶に残った問いと、まだ説明できない問いは何ですか。

## 5. 評価軸

| 軸 | 測るもの | 現行UIとの関係 |
|---|---|---|
| Recall | 用語、単位、宇宙の階層を取り出す | Recall |
| Concept | 距離と時間、見かけと実体などの関係を説明する | Concept |
| Reasoning | 条件を変えた新しい状況を予測する | Reasoning |
| Evidence / Data | 観測値と解釈を分け、複数証拠を結びつける | Dataの拡張候補 |
| Epistemic judgment | 確立事項、モデル、仮説、未知を主張単位で判断する | 横断評価 |

5軸目を直ちに製品の進捗スキーマへ追加しません。pilotの答案を見て、EvidenceとEpistemic judgmentを独立表示する教育上の利点があるかを判断します。

## 6. Pilotゲート

標本が小さいため、統計的有意差は主張せず、中央値、個々の変化、行動記録を併記します。`pilot-validated`には次を要求します。

以下の点数基準は製品リリースのための暫定ゲートであり、心理測定学的に妥当性が確立した合否点ではありません。答案と行動の対応を見て、Lesson Standard v1とともに見直します。

- 全参加者が、説明なしで最初のLessonを開始できる。
- 3人なら3人、4人なら3人以上、5人なら4人以上が18章を完了する。
- Pre/Post総合点の中央値が20ポイント以上改善し、Postの中央値が70%以上になる。
- Postで5軸すべての中央値が60%以上になる。
- 重大な科学的誤解を残す設問が、複数参加者で同じ原因により失点していない。
- 同じ場所で2人以上が進行不能、操作迷子、説明の読み飛ばしを起こした問題を修正する。
- 7〜14日後に、Postで得た改善量の80%以上を中央値で保持する。
- 修正後、原因となった箇所を少なくとも1人の初学者で再確認する。

数値基準を満たしても、誤った科学説明、アクセシビリティ上の進行不能、正答を誘導するだけの問題が残る場合は通過にしません。

## 7. 問題の優先度

| 優先度 | 定義 | 対応 |
|---|---|---|
| P0 | 科学的誤り、データ消失、進行不能、重大なアクセシビリティ問題 | pilotを止めて修正し、別ラウンドで再開 |
| P1 | 2人以上が同じ説明で誤解・離脱・操作迷子になる | v1.0前に修正して再確認 |
| P2 | 一人に起きた混乱、冗長、軽微な操作摩擦 | 頻度と影響を見て修正 |
| P3 | 好み、表記、将来案 | backlogへ記録 |

## 8. 成果物

- 記入済みの生ログ: Git管理外
- 匿名化したPre/Post/Delayed集計
- P0〜P3の問題一覧と修正履歴
- `level-0-report-template.md`から作る検証レポート
- pilotから確定した`ASTRAEA Lesson Standard v1`
- 転移課題を中心とするLevel 0 Final Assessment

検証レポートに根拠がそろうまで、Level 0を`validated`とは表示しません。
